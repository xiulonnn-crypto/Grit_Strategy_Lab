# 数据快照治理台 UI 稿 v4

## 本版调整

本版继续沿用同一设计包，针对新的 UI 评审意见做四项收敛：

- `待处理队列` 所在行上移到 `当前下钻` 上方，在 1960px 桌面首屏内可见；首屏顺序为标题、L1-L4 健康、待处理队列 + 因子影响摘要、当前下钻。
- `凭据与本机配置` 增加配置操作入口：冷却项可查看窗口，无效 key 可更换，缺失路径可配置，旧链路可暂不处理。
- `原始快照清单` 的动作列统一提供 `证据`；异常或部分可用行同时提供 `下钻`，下钻动作重定位到对应的横向下钻模块。
- 新增两个产品态弹层内容：`快照证据详情` 与 `刷新日志 / L1-L4 覆盖与入库明细`。刷新日志参考线上 `查看明细` 弹层，明确每个层级的当前覆盖、本次入库和入库来源；债券证据参考线上债券 tab 的曲线、资产腿准入、审计矩阵和质量审计信息。

桌面设计基准仍为 `1960px` 宽输出，左侧导航 `240px`，主内容区最大宽度 `1664px`。

## 设计目标

本稿对应 `#/snapshots` 的统一快照治理页。目标用户是本地量化研究与数据运维 operator，需要快速判断：

- L1-L4 哪些数据层已经可用于研究、因子诊断、回测或组合来源。
- 首屏有哪些可执行事项，并能直接进入修复、配置或下钻。
- 债券基础行情是否可进入资产腿创建和风险预算。
- 原始快照行的证据是什么，异常时应下钻到哪里。
- 本次刷新任务对每个层级实际入库了什么，来源链路是否可解释。

## 页面结构

1. 顶部标题区
   - 保持轻量 heading，不展示四个资产覆盖卡片。
   - 主按钮为“刷新基础行情”，辅助按钮为“查看刷新日志”。

2. L1-L4 数据层健康
   - 四张卡仍是页面首要判断。
   - L1 卡合并股票与债券：`股票 1266 / 1482 · 债券 7 / 7`。

3. 待处理队列 + 因子影响摘要
   - 位于横向下钻之上，必须出现在 1960px 首屏内。
   - 待处理队列只展示有明确动作的事项：修复、配置路径、查看台账。
   - 因子影响摘要把矩阵收敛为“允许动作”，完整映射进入下钻或证据弹层。

4. 横向下钻模块
   - 默认打开 `L1 基础行情`。
   - 四列结构：可用边界、可用证据、固定收益基础行情、不可用与修复。
   - 异常快照行的 `下钻` 操作应滚动并高亮该模块。

5. 原始快照清单
   - dense table 承载台账。
   - 正常行提供 `证据`。
   - 异常 / 部分可用行提供 `下钻 + 证据`。
   - 债券行的证据弹层使用线上债券 tab 内容：曲线点、资产腿准入、风险预算、审计矩阵、质量审计。

6. 凭据与本机配置
   - 读取 `/data-snapshots/provider-registry`。
   - 顶部显示 registry 汇总：45 注册来源、14 启用、11 可用、21 已配置 key/path、OpenBB 关闭。
   - 明细表包含操作列：
     - 冷却项：`查看窗口`
     - 无效 key：`更换 key`
     - 缺失路径：`配置路径`
     - 旧链路：`暂不处理`
     - 可用来源组：`查看来源`

7. 弹层状态
   - `快照证据详情`：展示该快照身份、状态、来源、覆盖、质量审计和可执行动作。
   - `刷新日志`：展示任务状态、刷新目标、阻断码、更新时间，以及 L1-L4 的当前覆盖、本次入库、入库来源 / 尝试来源和下钻动作。

## 证据弹层契约

证据弹层由原始快照清单的 `证据` 按钮触发。基础字段：

- 快照身份：`snapshot_id` 或债券 `bond_fixed_income::*` id。
- 当前状态：已就绪、部分可用、待补、阻断。
- 覆盖 / 行数：覆盖符号、总符号、行数或债券曲线点。
- 来源：正式入库来源、尝试来源、不可用来源。
- 质量：阻断码、审计状态、缺失字段、被推断字段。
- 影响：因子族、资产腿、风险预算、Full Ready 或 PIT 准入。
- 动作：异常时提供“下钻到 L1/L2/L3/L4”，正常时只提供关闭或查看来源。

债券证据弹层的固定内容：

- 曲线点：3M 3.69%、2Y 3.95%、10Y 4.45%、30Y 5.02%。
- 资产腿准入：7 / 7 可创建，7 / 7 可入风险预算。
- 审计：10Y-2Y 利差 +50 bps，处于 -100 至 300 bps 审计带内。
- 质量：价格一致性通过；久期 / 凸性完整；T-Bill 应计利息豁免已记录。
- 来源：`us_treasury_xml` 与 `iShares`，不得展示静态 preset 行。

## 刷新日志弹层契约

`查看刷新日志` 弹层使用当前刷新任务作为口径。当前样例为：

- 任务：`snap_57ae046824c9`
- 状态：`INCOMPLETE`
- 模式：`repair`
- 目标：`price / corporate`
- 阻断码：`CORPORATE_ACTIONS_INCOMPLETE`
- 更新时间：`2026-05-19T10:55:58Z`

层级表必须包含：

- L1 当前覆盖：价格 `1266 / 1482`、公司行为 `1030 / 1482`、债券 `7 / 7`。
- L1 本次入库：`0 符号 / 0 行`。
- L1 入库来源 / 尝试来源：EODHD、SEC EDGAR、Tiingo、Yahoo；Polygon 凭据无效，yfinance 未安装。
- L2 当前覆盖：`940 / 1482 · 140734 行`；来源 SEC EDGAR；本任务未入库。
- L3 当前覆盖：一致预期 `3855 行`、卖空 `2824 行`；来源 Alpha Vantage、FINRA Short Volume；本任务未入库。
- L4 当前覆盖：宏观 `10 / 10`、期权偏度 `729 / 729`；来源 FRED Macro Series、Polygon 历史快照；本任务未入库。

弹层中的“当前缺口”列必须使用动作按钮，例如 `下钻 L1 缺口`、`查看平衡观察项`、`查看证据`、`下钻依赖`。

## Provider Registry 映射

当前线上真实状态来自 `/data-snapshots/provider-registry`：

- `TIINGO_API_TOKEN`：已配置；Tiingo 价格与公司行为链路处于限流冷却，Tiingo Symbology 可用。
- `ALPHAVANTAGE_API_KEY`：已配置；Alpha Vantage 处于冷却中。
- `MASSIVE_API_KEY`：已配置但 Polygon.io 返回 `invalid_credentials`，标记为“凭据无效”。
- `CRSP_DATA_PATH`：缺失，影响长历史、退市收益、身份确权和 30Y Full Ready 归档。
- `NORGATE_DATA_PATH`：缺失，影响长历史补价、退市身份和精修来源。
- `IEX_TOKEN / IEX_CLOUD_TOKEN`：缺失，但属于旧链路，不影响当前主链路。
- `FMP_API_KEY`、`FINNHUB_API_KEY`、`EODHD_API_TOKEN`、`SEC_USER_AGENT`：已配置并可用于历史成分、身份、定向修复与 SEC 证据链。
- OpenBB 当前关闭；OpenBB provider 不作为本页可执行修复入口。

## 交互契约

- 点击 L1-L4 卡片：切换横向下钻模块内容。
- 点击待处理队列 `修复 L1`：调用 `POST /admin/snapshot-refresh-jobs`。
- 点击凭据缺失项 `配置路径` / `更换 key`：展开同页配置行，显示输入框、复制命令和重启提示。
- 点击快照清单 `证据`：打开证据弹层。
- 点击快照清单 `下钻`：重定位到对应横向下钻模块并高亮相关证据块。
- `#/snapshots?tab=bond` 作为兼容入口保留，但不渲染独立债券页；进入后应滚动并高亮 L1 横向下钻中的固定收益基础行情。

## 响应式与截图基准

- 桌面基准：`1960px` 宽，左侧导航 `240px`，内容最大宽度 `1664px`。
- `>= 1280px`：待处理队列在横向下钻上方；证据与刷新日志弹层可使用双栏状态展示在设计包内。
- `768px - 1279px`：待处理队列、因子摘要、横向下钻改为单列或两列。
- `< 768px`：隐藏侧边栏菜单，表格横向滚动，弹层全宽。
